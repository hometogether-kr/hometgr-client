# 모드 전환과 내비게이션

현재 보완 작업 브랜치: `feat/listing-registration-guest-landing`.

## 적용한 동작

- `/`는 게스트 메인이다. 이전 선택형 첫 화면을 대체한다.
- `/intro/guest`는 `/`로 영구 리디렉션한다.
- 집주인 메인은 `/intro/host`다.
- 두 메인과 용도가 명확한 화면에서는 URL이 저장값 및 서버 role보다 우선한다. `/listing/**`·`/host/reservations/**`는 집주인, `/rooms/**`·`/reservations/**`·`/favorites/**`·`/faq/guest/**`는 게스트다.
- 두 메인에만 텍스트 전환 링크를 표시한다. 로그인 없이도 이용 가능하다.
- 반대 모드로 전환하면 해당 메인으로 이동한다.
- PC 헤더와 모바일 메뉴는 게스트에서 방 찾기, 집주인에서 방 내놓기만 표시한다.
- 로고 및 서비스 소개 링크는 현재 모드의 메인으로 연결한다.
- 로그인·마이페이지 등 공통 화면에서는 저장된 모드를 사용하고, 유효한 값이 없으면 게스트를 기본으로 한다.
- 메뉴 표시를 사용자 정보 조회 성공 여부에 묶지 않는다. 세션 조회가 지연되거나 실패해도 탐색·등록 메뉴가 사라지지 않는다. 실제 접근 권한 검사는 기존 서버/API 정책을 따른다.
- 등록 1~10단계의 Suspense 대기 화면에서도 공통 헤더를 표시한다. 2~4단계는 초안 조회 중·조회 실패·잘못된 초안 주소에서도 헤더를 유지하며, 실패 화면에서 임시저장 목록으로 돌아갈 수 있다.
- 모바일 등록 단계는 뒤로가기와 함께 메뉴 버튼을 제공한다. 메뉴는 Escape로 닫히고, Tab 포커스를 내부에 유지하며, 닫힐 때 이전 버튼으로 포커스를 돌려준다.
- 회원은 계정별로, 비회원은 방문자 키로 모드를 저장한다. 서버 권한은 변경하지 않는다.
- 직접 진입, 새로고침, 뒤로가기 때도 메인 URL을 기준으로 저장값을 갱신한다.

## 역할 없는 가입

- 카카오 로그인 → 약관 동의 → 기본 정보 확인(`/onboarding/profile`) → 가입 완료 순서로 진행한다.
- 기본 정보는 이름과 연락처이며, 가입 요청에 `role`을 보내지 않는다.
- 기존 `/onboarding/role` 주소는 기본 정보 화면으로 리디렉션한다.
- 로그인 시작 시 모드를 30분 동안 서버 쿠키에 보관하여 가입 완료 후 해당 메인으로 이동한다. 저장값이 없거나 유효하지 않으면 게스트 메인으로 이동한다.
- 기존 회원 로그인도 로그인 시작 시 선택한 모드의 메인으로 이동한다.
- 기존 API 응답의 role과 관리자 권한 판별은 유지한다.

## 별도 후속 작업

상담 폼 연동 및 보류 사항은 `host-consultation-integration.md`에 기록한다. 관리자 UI는 추후 작업이다.

## 수동 점검

1. `/`에서 게스트 소개, 방 찾기, 집주인 전환 링크를 확인한다.
2. 전환 후 `/intro/host`, 방 내놓기, 게스트 전환 링크를 확인한다.
3. 새로고침과 뒤로가기 후 경로와 메뉴가 일치하는지 확인한다.
4. 로그인 화면 등 공통 화면에서 전환 링크가 없고 모드는 유지되는지 확인한다.
5. 모바일 375px에서 전환 링크와 메뉴가 겹치지 않고 동일하게 동작하는지 확인한다.

## 2026-10-08 네비게이션 유지 보완

- 원인: 메인 외 화면에서 세션 사용자 ID가 없으면 메뉴 준비 상태가 false로 남았다. 등록 2~4단계에서는 초안 조회 대기·오류 반환에 헤더가 없었고, 모바일 등록 단계에는 메뉴 진입 버튼이 없었다.
- 로컬 Edge에서 모든 API를 503 모의 응답으로 대체하고 외부 요청을 차단해 확인했다. `/rooms`의 방 찾기, `/listing/new`의 방 내놓기 표시, 호스트 하위 메뉴의 키보드 열기, 등록 2단계 초안 오류 화면의 헤더·복귀 링크, 모바일 오류 화면 메뉴·Escape·포커스 복귀를 확인했다.
- 실제 로그인·배포 API는 검증하지 않았다. 페이지 전환·뒤로가기·새로고침 묶음 검증은 시간 초과로 완료하지 못했다. 모바일 정상 등록 폼의 새 메뉴 버튼과 전체 10단계 전환도 추가 확인이 필요하다.
- 탐색 목록 SSR에서 상대 BFF URL(`/api/bff/rooms`) fetch 오류와 클라이언트 렌더링 전환이 별도로 관찰됐다. 네비게이션은 유지되며, 이 목록 조회 문제는 검색·필터 단계에서 확인한다.
- C 드라이브 여유 공간이 약 1.25GB로 낮아 사용량을 조사했다. `.next` 약 1.88GB, Windows 페이지 파일 할당 약 22GB를 확인했으며 기존 의존성·캐시는 삭제하지 않았다.
- 자원 부족으로 병렬 검사를 중단하고 단독 검사로 전환했다. 힙 제한을 둔 ESLint(1GB)와 TypeScript(1.5GB)는 메모리 부족으로 종료되었으므로 통과로 계산하지 않는다.
- 개발 서버·브라우저 종료 후 여유 공간이 약 6.3GB로 회복됐다. 기본 설정으로 순차 재실행한 최종 `tsc --noEmit --incremental false`와 변경 파일 ESLint 검사는 모두 통과했다. `git diff --check`도 통과했다. 임시 검증 스크립트·스크린샷은 제거했고, 커밋·푸시·배포·실제 데이터 변경은 하지 않았다.
