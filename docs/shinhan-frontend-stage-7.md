## 구현

개발 전용 경로는 `/shinhan/dev/guest/budget`, `/shinhan/dev/guest/demand`다. 운영 모드에서는 `notFound()`이며 실제 접수 버튼은 비활성이다. 운영 하위 신청 경로를 이번 단계에서 확정하지 않았다.

- 예산 매칭: 월 예산, 자유 위치, 희망 입주일 → 공통 공간 예시·전화번호·필수 동의.
- 수요조사: 자유 위치, 최소·최대 예산, 희망 입주일, 계약기간, 성별 → 같은 공간 예시·전화번호·필수 동의.
- 메인의 검색 입력·지역 카드·방 보기와 예산 배너·플로팅을 개발 화면에 연결했다. 입력한 위치 또는 카드의 실제 지역을 수요조사 초안으로 넘기며 URL·브라우저 저장소에 기록하지 않는다.
- `/shinhan/guest`의 얇은 route를 `(intake)` 공통 layout 아래로 옮겼다. URL은 유지하며 메인 → 신청 → 전문 왕복의 React 상태를 공유한다. 다른 신청을 시작하면 별도 빈 초안으로 시작하고 새로고침에서는 초기화한다.
- `app`은 route·운영 제한, `pages-layer`는 헤더·본문·푸터 조합, widget은 Server 소개·사진과 Client 입력 흐름, feature는 초안·검증·공통 입력을 담당한다. 기존 호스트 초안·전문 복귀 방식도 같은 매핑으로 유지한다.

예산은 원 단위 숫자로 보관하고 화면에서는 만 원으로 표시한다. 20만 원부터 100만 원까지 1만 원 단위이며 슬라이더와 직접 숫자 입력을 함께 제공한다. 시안의 45만 원·40~60만 원은 확정 기본값이 아니므로 자동 응답으로 저장하지 않고 초기 값은 미입력이다. 범위 슬라이더의 표시 위치와 실제 선택된 값은 구분한다. 최소·최대가 같아도 허용하고 역전하면 오류를 표시하며 자동으로 바꾸지 않는다.

지역 필드는 두 경로에서 같은 컴포넌트·Zod schema를 쓴다. 원문을 작성 상태에 유지하고 검증 시 양 끝 공백을 제거하여 1~200자를 확인한다. 지도·주소 검색·자동완성을 추가하지 않았다.

날짜는 기존 `shared/ui/calendar`의 단일 선택을 재사용한다. 서울 기준 오늘부터 선택할 수 있고 실제 날짜를 `YYYY-MM-DD`로 보관하며 UTC 변환으로 날짜를 바꾸지 않는다. 달력 열기·닫기·Escape·외부 클릭·포커스 복귀를 제공한다. 계약기간 13개 선택지와 여성/남성을 기본 선택 없이 표시한다. `MONTH_12`와 `MONTHS_12_PLUS`를 별도로 유지한다.

조건 검증 후 접수 전 예시·연락처 단계로 이동한다. 예산 경로의 ‘찾았어요’는 유지하며 실제 매물 검색은 실행하지 않는다. 수요의 조건 수정은 수요 경로로 돌아간다. 전문을 열었다가 돌아와도 현재 단계와 조건·전화번호·필수 동의가 유지되며 동의를 자동 체크하지 않는다. 개발용 형식 확인은 실제 저장 성공과 명확히 구분한다.

## 에셋·시안 차이

기존 `guest/budget-banner.png`를 소개에 재사용한다. Figma 예산 결과의 사진과 기존 소개 사진은 달라 원본 3장을 `public/images/shinhan/guest/example-{private-room,living-room,kitchen}.png`로 내려받았다. 각각 1448×1086이며 Next Image로 표시한다. 임시 Figma URL을 코드에서 사용하지 않는다.

수요 Figma는 여러 사진을 합친 별도 콜라주다. 사용자 확정 ‘공통 예시 사진’과 모바일 9.1의 개인방 → 거실·주방 배치를 우선하여 두 경로에 예산 시안의 동일 3장을 적용했다. PC는 큰 개인방과 오른쪽 거실·주방, 모바일은 큰 개인방 아래 거실·주방 두 장이다. 공간별 이름과 공통 예시 안내를 표시한다.

기존 Dropdown은 키보드 선택 지원이 부족해 이번 계약기간 필드는 네이티브 select를 사용했다. 범위 예산은 시안의 두 손잡이와 함께 각각의 숫자 입력을 제공한다. 외형을 이유로 키보드·정확한 1만 원 선택을 제한하지 않는다.
