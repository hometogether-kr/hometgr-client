## 구현

- `app`의 두 얇은 route가 `pages-layer/shinhan-host-intake`를 렌더링한다. 페이지는 헤더·개발 안내·호스트 widget·푸터를 조합한다.
- `widgets/shinhan-host-estimate`, `widgets/shinhan-host-registration`은 정적인 안내·이미지를 Server Component에 두고 입력·검증만 작은 Client Component로 분리한다.
- 기존 `features/shinhan-intake`의 초안 상태를 공유한다. 경로가 다른 신청으로 바뀔 때 새 초안을 만들고, 개인정보 전문 왕복에서는 같은 초안과 단계를 유지한다. 임의 URL을 복귀 대상으로 받지 않는다.
- 전화번호와 필수 동의 UI를 별도 컴포넌트로도 제공하여 방 등록의 전화번호 → 주거 형태 → 위치 → 동의 순서를 유지한다.
- API DTO와 분리된 초안을 유지하며 Zod로 입력 형식을 검증한다. 원문은 작성 상태에 유지하고 검증 결과만 사용한다. 새로고침 복원·개인정보의 URL 또는 브라우저 저장소 기록은 추가하지 않는다.

견적은 기존 `shared/ui/address-search-dialog`의 카카오 검색·선택 결과를 사용한다. 기본 주소 직접 입력과 주소 미선택의 평균값 우회는 제공하지 않는다. 동·호수는 각각 선택 입력·최대 40자이며, 가구 네 종류는 보유 중/구매 예정/없음으로 구분한다. 실제 견적 화면의 새 초안은 기획 6.4에 따라 네 가구 모두 ‘없음’이고 화장실은 1개 또는 2개를 선택한다. 기존 공통 개발 미리보기의 미응답 상태는 별도로 유지한다.

조건 검증을 통과하면 연락처·동의 화면으로 이동한다. 서버 계산·저장이 아직 연결되지 않아 계산 중 애니메이션이나 계산이 끝났다는 문구를 추가하지 않았다. 저장 전 수익은 마스킹하고 ‘예상 수익 확인하기’는 비활성화한다. 개발용 형식 검증은 접수 성공과 구분한다.

방 등록은 Figma대로 한 화면이다. 위치는 자유 입력·공백 제외 1~200자이며 자가와 월세/전세 모두 유효하다. 사용자 확정 사항에 따라 필수 동의와 전문 링크를 추가했다. ‘다음’은 저장 API 연결 전 비활성 상태이고, 심사 안내나 완료로 이동하지 않는다.
