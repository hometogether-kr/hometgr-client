## 검증 방법과 범위 제한

기존 Node의 JSON 파싱·assert·crypto 및 날짜/정수 계산을 임시 명령으로 사용했다. 테스트 프레임워크·의존성을 추가하지 않았다. 바뀐 기간/상태/예시와 버전 영향만 검증하고, unchanged 신청 흐름·기존 전체 앱 테스트는 반복하지 않았다.

앱 코드·수집기·실행 스크립트 변경, 앱 테스트·lint·format·build, dev server·브라우저, 실제 신청·걱정·소개서·알림·시트·수집기 호출, 배포·push·merge는 실행하지 않았다.

공개 보완 억제는 모든 이전 실제 공개값과 후보의 기여 관계를 증명할 수 있을 때만 수치를 공개하는 보수적 기술안이다. 구현 시 보관 한도/용량 때문에 증명할 수 없으면 계속 억제될 수 있다. 실제 운영 규모·성능을 검증한 것으로 표시하지 않으며 관리자 재검토 대상에 포함한다.

최종 문서·예시 해시는 manifest.json, 관리자 재검토 및 동일 버전 확인은 agreement.md에 기록한다.
