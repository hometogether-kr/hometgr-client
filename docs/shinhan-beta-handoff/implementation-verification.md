## 실제 브라우저와 로컬 합성 응답

실행 명령: node scripts/shinhan-beta-local-mock.mjs --dev --fresh-origin

- 고객 개발 서버: http://127.0.0.1:3320
- 합성 서버: http://127.0.0.1:4319
- --fresh-origin 없이 실행하면 고객 포트는 3319다. 합성 서버는 동일한 4319다.
- 합성 서버는 루프백·메모리 전용이며 가짜 전화번호 01000000000만 받는다. 소개서·알림 및 미정의 요청은 차단한다. 실제 Apps Script나 관리자 집계를 구현하지 않는다.
- 기존 신청 BFF의 대상만 실행 프로세스 안에서 합성 서버로 바꾼다. 저장소 환경 파일이나 운영 키는 수정하지 않는다.

## 관리자 인계와 운영 연결 전 확인

관리자 측은 같은 동결 버전의 수집기·집계와 대시보드를 담당한다. 고객 측에는 서명 수집 요청을 보내는 분석 BFF와 메모리 합성 도구만 있다. 요청·응답·예시 변경이 없으므로 계약 재작성이나 운영 기준 재결정은 필요하지 않다.

다음 값은 운영 연결 전에 관리자가 제공하거나 서버 담당과 맞춘다. 비밀값은 채팅·문서에 기록하지 않고 서버 설정으로만 주입한다.

- BETA_TRACKING_WEB_APP_URL 및 별도 쓰기 키 BETA_EVENT_WRITE_SECRET(32~256자). 관리자 읽기/공개 읽기 키와 분리한다.
- BETA_TRACKING_CONTEXT_ID, BETA_RUN_ID, BETA_DATASET, BETA_START_AT, BETA_TRACKING_ALLOWED_ORIGINS, BETA_TRACKING_MODE, BETA_TRACKING_ENABLED의 적용값. run/context는 달력 집계 기간이 바뀐다고 교체하지 않는다.
- 운영 /api/beta ingress와 요청 제한, 실제 배포 대상, 수집기 17열·중복 처리·90일 정리 운영 책임.
- 실제 분석 연결 검증의 대상·요청 수·예상 신규 행 수와 확인 담당. 운영 수집/공개 활성화는 별도 지시로 진행한다.

기존 인증·DB·공통 신청 API 계약의 변경 요청은 현재 없다. /api/beta 라우팅·요청 제한과 비밀 설정을 기존 서버 운영에 반영해야 한다면 서버 담당 작업으로 전달한다.
