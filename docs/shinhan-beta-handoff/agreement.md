## 구현 메모와 한계

관리자 채팅에서 사용자는 공개 최신성 문구 보완 설명을 듣고 “그냥 넘어가자...”라고 지시했다. 아래 메모를 남기며 해당 문구만으로 새 계약판이나 추가 fixture를 요구하지 않는다.

- 공개09시 snapshot 이후의 정상 신규 이벤트(received_at>공개 as_of)와 내부 dirty만으로 공개 값을 즉시 오래됨으로 표시하지 않는다. 다음 공개 갱신 대상으로 처리한다. 공개 관찰범위(received_at<=as_of)의 확인된 누락·부분 실패와 공개 갱신 실패는 구분한다.
- 공개 보호는 후보와 과거 실제 공개 숫자의 기여 관계에 대한 보수적 규약이다. 외부 배경지식을 포함한 모든 재식별 방지 증명으로 확대하지 않는다.
- 90일 보관 한도 안에서 과거 공개값의 안전성을 증명할 수 없으면 공개 수치가 장기간 또는 기한 없이 억제될 수 있다. 새 key/run/policy 이름으로 이전 공개를 지우거나 무기한 식별 저장소를 추가하여 우회하지 않는다.
- 공개 이력 완전성을 확인할 수 없으면 숫자를 공개하지 않는다. 공개 여부가 불확실했던 이력을 없던 일로 처리하지 않는다.

이 메모는 실제 가용성·성능 검증이나 구현 재개 지시가 아니다. 개발 재개 지시를 받은 이후 변경 범위의 구현·검증 항목으로 사용한다.
