개발 API 계약 확인

  • 대상: dev-api.hometogether.kr. 공개 GET만 실행했으며 데이터 변경·슬랙 발송은 하지 않았습니다.
  • GET /rooms/districts?sido=서울특별시 → HTTP 200, 중랑구 1개. 각 항목은 sido/sigungu/label 이름 값.
  • GET /rooms → HTTP 200, 공개 매물 1개. 중랑구 조건은 1개, 노원구 조건은 0개로 구분.
  • 목록 title/subtitle과 비회원 v2 상세 preview.title/preview.subtitle 일치 확인. 회원 v2는 최상위 title/subtitle을 사용하며 실회원 응답은 후속 검증.
  • 이번 구현은 URL 행정 코드를 유지하고 API에는 시도·구 이름을 전달합니다. 구 목록에 없는 유효한 서울 구 URL도 검색 결과 없음으로 처리합니다.

검증: 전체 TypeScript 검사·변경 파일 린트·Prettier 검사 통과. 공개 API HTTP 200, 구 조건에 따른 1개/0개 결과와 목록·상세 제목/부제목 일치 확인. 신규·레거시 × 회원·비회원 매핑, 선택 부제목 미입력/공백, 월세 30→30만원, 가격 미입력→가격 문의, 제거한 필터의 기존 URL 무시, 성별·정렬 보존, 잘못된 구 응답 거절, 모의 응답 호환 검증 통과. 브라우저는 webview 연결 실패로 화면 검증 미완료. 실회원 API·운영 배포는 검증하지 않았습니다. 개발 드라이브 여유 3.4GB 확인 후 서버를 중단했으며 활성 캐시는 삭제하지 않았습니다.

3단계 검색 UI 통합 검증

홈의 구 선택·탐색 검색창·필터 모달이 같은 districts 조회, 지역 필터 변환, URL 생성, 기존 목록 API를 사용합니다. 구 선택은 초안만 바꾸고 검색/완료에서 적용합니다. URL 행정 코드로 검색창·지역 칩·모달 선택을 복원하며, 현재 구 목록에 없어도 유효한 서울 구의 URL 선택은 유지합니다.

  • 전체 TypeScript·변경 파일 ESLint·Prettier 통과. 실제 UI 콜백 실행으로 서울 25개 구의 홈/검색창/모달 URL·API 요청 일치, URL 복원, 다른 필터·정렬 유지, page=1 초기화 확인.
  • 실제 개발 API·브라우저: 홈 districts 중랑구 선택 후 검색 → /rooms?sido=11&sigungu=11260. 모달에서 같은 구 선택 후 완료도 같은 URL·매물 1개·동일 매물 ID. 이동 직후 모달의 중랑구 선택 상태 확인.
  • 새로고침·뒤로가기·앞으로가기의 선택 상태 복원, 전체 목록 초기화 확인. 브라우저 콘솔 오류·경고 없음. 공개 구 조회·목록 BFF HTTP 200.
  • 브라우저 초기 연결 지연은 개발 서버의 최초 컴파일 이후 해소되었습니다. 실제 구가 1개이므로 구 간 결과 차이·다중 페이지·모바일 전체 회귀는 8단계에서 추가 확인합니다. 디스크 여유가 5GB 미만으로 내려가 .next 사용량을 조사했고 활성 캐시는 삭제하지 않았습니다.
