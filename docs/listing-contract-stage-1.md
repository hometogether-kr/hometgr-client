## 반영 내용

| 항목 | 처리 |
| --- | --- |
| 건물 유형 | 신규 입력 5종. 읽기는 `villa`를 그대로 허용하고 빌라로 표시. 기타 설명 필수 |
| 거주 인원 | 미선택 `null`과 실제 `0` 구분. 0~100. 0이면 구성·성별 null/숨김, 양수이면 필수 |
| 면적 | 집 전체 `areaRange`만 입력. 미상 허용. `privateRoomSize` 신규 요청·응답 모델·초기값 제거 |
| 주소 | 도로명·지번·대략적 위치 중 하나 이상. 도로명/지번/법정동/시도/시군구/건물 동/호수 보존 |
| 공개 상세 | 동·호수·자유 상세주소는 일반 상세 DTO에서 사용하지 않음 |
| 자동저장 | 700ms debounce, 서버 PATCH 연결, 최신 version을 순차 사용. 완료 저장·이전 이동 전 대기 중 입력 저장 |
| 재개 | 서버 autosaves를 도메인 모델에 보존. 완료 데이터에 부분 snapshot을 병합하고 필드별 Zod 검증 |
| 레거시 복구 | villa 재선택 안내. 제거된 면적 필드 경고. 복원 가능한 다른 입력 보존 |
| 만료·충돌 | 서버 expiresAt 유지. 만료 후 쓰기 차단. 409 후 자동 덮어쓰기 중단. 목록에 정확한 만료 시각 표시 |
| route | 변경 단계의 조립을 pages-layer/features로 이동. route는 Suspense와 페이지 렌더링만 유지 |

새로고침 시 완료된 서버 snapshot을 복원한다. 저장 대기/진행 중 페이지를 떠나려 하면 브라우저의 미저장 경고를 사용한다. 사용자가 경고를 무시하고 강제 종료한 입력의 저장을 보장하지 않는다.

## 카카오맵 후속 연결을 위한 주소 처리

[Kakao 우편번호 공식 가이드](https://postcode.map.kakao.com/guide)를 대조했다.

- 공급자 `bcode` → `legalDongCode`, `bname` → `legalDongName`.
- `roadAddress`와 `jibunAddress`를 별도로 저장한다. 선택 주소의 `address`는 선택 유형에 맞는 필드에만 보완한다.
- `autoRoadAddress`/`autoJibunAddress`는 예상 주소이므로 확정 주소로 치환하지 않는다.
- 우편번호·건물명은 공급자/UI 정보다. 서버가 받지 않는 필드를 요청에 추가하지 않는다.
- 동·호수는 건물 주소에 합치지 않는다. 이번 단계는 좌표 생성·지오코딩·지도 렌더링을 하지 않는다.
- 후속 지도는 서버의 주소 확인 상태, 공개 대상별 좌표 정책을 대조해 연결해야 한다.

## 검증

- TypeScript: `node node_modules/typescript/bin/tsc --noEmit --incremental false`.
- 변경 TS/TSX 파일 ESLint 검사 및 Prettier 적용.
- 초기 샌드박스 실행에서 의존성 realpath 접근 오류로 타입 해석이 깨졌다. 정상 권한에서 재검사하여 의존성 코드 수정 없이 통과했다.
- 별도 테스트 프레임워크/패키지는 설치하지 않았다. 번들 Playwright와 로컬 임시 검증 스크립트를 사용했다.
- dev 서버의 `API_BASE_URL`을 도달 불가능한 로컬 주소로 지정하고, 브라우저의 모든 API 요청을 모의 응답으로 가로챘다. 가짜 로컬 세션 쿠키만 사용했다.
- 브라우저 주요 시나리오: 신규 유형/기타 설명, 대략적 위치, 0명/양수 조건부 입력, 면적 미상, 크기 없는 개인 공간, 주소 구조 보존, 지번 단독, 새로고침, 레거시 경고/재선택, 모바일 가로 넘침, 충돌 후 쓰기 중단, 만료 후 쓰기 차단.
- 주요 시나리오에서 가로챈 쓰기 27건, 원격 쓰기 0건, pageerror 0건.
- 추가 브라우저 검증: 실제 이어쓰기 카드가 서버 nextStep을 따름, 0명 snapshot 재개, 입력 직후 다음 버튼으로 PATCH→PUT 순서/연속 version 유지, 만료 시각 불변, 라디오 Space/ArrowDown 조작, 기타 공간 입력, 잘못된 공급자 응답 거절과 기존 입력 유지. 수정 후 pageerror 0건.
- 재개 화면의 기존 중첩 버튼 hydration 오류를 제거하고 긴 만료 안내의 줄바꿈을 허용했다. 변경 단계의 중첩 라벨도 올바른 id/htmlFor 연결로 수정했다.
- 순수 스키마/매핑 검증: 인원 -1/0/100/101/소수/null, 기타 공백, 세 주소 대안, 예상 주소 제외, 잘못된 공급자 응답 거절, 상세 null 파싱, villa 읽기, 민감한 주소 필드 제외, snapshot의 다른 필드 보존.

## 구현 확인과 미검증

API migration에는 기존 villa 초안의 위치 데이터를 autosave로 옮기고 완료 단계에서 위치를 제외하는 복구 처리가 있다. 클라이언트는 이 응답을 받아 재선택을 안내한다. 이 코드의 존재를 확인했으며 배포 DB 적용 여부는 확인하지 않았다.

배포 API, 실계정 인증, 실제 Kakao 검색 서비스의 외부 통신, 실제 제출/사진 업로드, 관리자 주소 확인·게시, 배포 서버의 공개 상세 정책은 실행 검증하지 않았다. 모의 API 검증은 배포 연동 검증을 대신하지 않는다. 현재 확인한 계약상 추가 API 변경은 필요하지 않다.

네비게이션 개편, 검색·필터, 카카오맵 연결, 관리자 기능은 후속 단계로 남긴다.
