# 기술 결정 기록

- 대상 저장소의 `docs/decisions/README.md`와 관련 결정·기존 설계 문서를 먼저 읽는다. 없으면 부재를 밝히고 관련 문서를 조사한다.
- 결정이 필요한 배경·제약·대안·영향을 확인한다. 기존 승인 결정과 충돌하면 해당 구현을 멈추고 알린다. 기록 요청만으로 미확정 선택을 승인하지 않는다.
- `docs/decisions/`의 번호 파일 중 최대 번호 + 1을 네 자리로 사용한다. 번호 파일이 없으면 0001부터 시작한다. 저장 직전 중복을 확인하고 기존 파일을 덮어쓰지 않는다.
- 사용자 승인 또는 세션에서 이미 확정된 선택은 승인 상태로 기록한다. 미결정이면 제안 상태로 남기고 필요한 질문을 정리한다. 구현 전 초안 → 선택 확정 → 구현 순서를 따른다.
- 파일과 인덱스를 함께 갱신한다. 이전 결정을 바꿀 때는 이전 문서를 삭제하지 않고 대체 관계를 양쪽에 기록한다. 과거 결정을 소급해 승인으로 만들지 않는다.

## 기록 형식

```markdown
# NNNN. 제목

- 날짜:
- 상태: 제안 / 승인 / 기각 / 대체됨
- 결정자·근거:
- 관련 기능 명세·계약·이전 ADR:

## 배경과 제약

## 결정 또는 제안

## 대안과 선택 근거

## 영향과 비용

사용자·화면·데이터·운영·복구에 미치는 영향. 확인되지 않은 것은 확인 안 됨.

## 재검토 조건과 미확인 가정

구체적인 조건이 없으면 미정으로 남기고 어떤 근거가 더 필요한지 적는다.

## 구현·검증 상태

결정 승인과 구현 완료는 별도다. 실제 결과 링크를 남긴다.
```

인덱스에는 번호·제목·상태·날짜·대체 관계·관련 문서 링크를 기록한다. 이 스킬 자체는 선택한 기술의 구현이나 배포를 허가하지 않는다.
