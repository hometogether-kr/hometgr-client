# 변경 설명

- 대상은 프론트를 다루지만 백엔드·인프라 경험은 적은 홈투게더 PM이다.
- 비교 base·head·작업 트리 포함 여부를 명시한다. 저장소 기본 브랜치나 관련 PR로 기준을 확인할 수 없으면 질문한다. 기존 사용자 변경과 이번 작업이 섞이면 확인 가능한 범위만 설명한다.
- 관련 diff·호출부·화면·명세·ADR·실제 검증 결과를 확인한다. 코드가 보여주는 동작과 문서에 기록된 의도를 구분한다. 버린 대안은 근거가 있을 때만 설명한다.
- 파일별 한 줄 요약을 제공하되 파일이 많으면 기능별로 묶는다. FSD 레이어와 확인된 화면·경로를 연결하고, 확인된 영향과 가능성 있는 위험을 구분한다.
- 수용 기준별 검증 근거와 실패·미실행을 밝힌다. 실행하지 않은 검사나 확인하지 않은 화면을 성공으로 표현하지 않는다.
- 복구는 코드 되돌리기로 충분한지, API 호환·데이터 변경·외부 자원의 복구가 필요한지 확인한다. 설명만 하고 실제 복구는 수행하지 않는다.
- PM에게 필요한 용어와 리뷰 질문만 추가한다. 개수를 채우지 않는다.
- 확인되지 않은 의도·영향·복구 가능성은 `확인 안 됨`으로 남긴다. 이 스킬 자체는 코드 수정·PR 게시·메시지 발송을 허가하지 않는다.
