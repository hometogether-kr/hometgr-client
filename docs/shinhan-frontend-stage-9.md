## 구현

기존 호스트 견적 연락처 화면의 실제 **예상 수익 확인하기**는 계속 비활성이다. 주택 조건·연락처·필수 동의가 유효할 때만 별도의 **결과 화면 미리보기 (개발용)**로 `/shinhan/dev/host/followup`에 진입한다. 운영 모드에서는 `notFound()`이고 모델 생성도 development에서만 허용한다. 직접 진입 또는 새로고침으로 스냅샷이 없으면 호스트 견적부터 작성하도록 안내한다.

수익은 계약의 고정 예시다. **노원구 / 침대·옷장 보유 / 책상 구매 예정 / 의자 없음 / 화장실 2개**에 대한 월 **425,000~525,000원**, 연 **5,100,000~6,300,000원**, 규칙 버전 `hometogether-rent-seoul-v1.0.0`을 표시한다. 사용자 입력으로 프론트 계산식을 실행하지 않는다. 예시 입력·계산 결과와 실제 작성 조건의 깊은 복사본을 분리하고, 화면에도 작성 조건의 실제 결과가 아님을 표시한다. 당시 예시와 규칙 버전은 걱정 화면에서 돌아와도 바뀌지 않는다.

수익 화면의 **입력 정보 수정**은 카카오 기본 주소·동·호수·가구·화장실·연락처·동의를 유지한 기존 조건 단계로 돌아간다. 수정 후 새 미리보기를 시작하면 새로운 작성 조건 스냅샷을 만들며 이전 걱정 선택·선택 동의·확인 응답을 자동 승계하지 않는다. 실제 새 견적 ID·요청 키와 과거 견적 영구 보존은 API 연동 단계에서 검증한다.

호스트 걱정은 계약의 `YOUNG_PERSON`, `LIFESTYLE`, `PRIVACY`, `RENT_MANAGEMENT`, `PROCESS`, `UNSURE` 여섯 코드를 사용한다. 여러 항목 선택과 개발 예시 동의 후 소개서 안내로 진행할 수 있다. 빈 목록에 명시적으로 동의한 응답과 아직 응답하지 않은 상태를 구분한다. **예상 수익 다시 보기**는 같은 결과로, **걱정 선택 다시 보기**는 기존 선택을 유지하는 걱정 화면으로 돌아간다.

미동의 자동 진행을 제품 동작으로 확정하지 않았다. 별도 **소개서 안내만 미리보기 (개발용)**는 화면만 이동하며 응답·선택·동의를 변경하거나 `SKIPPED`로 기록하지 않는다. 선택 동의는 개발 예시임을 표시하고, 연결된 **기본 신청 개인정보 전문**에 걱정 항목 선택 동의는 포함되지 않는다는 설명을 제공한다. 승인된 선택 전문·버전을 임의로 작성하지 않았다.

소개서 화면은 청년 소개·입주 시기와 기간·생활 습관 안내와 부담 없이 살펴볼 수 있다는 원문을 유지한다. **소개서만 먼저 받아보기**는 비활성이며 실제 저장·발송·접수 완료를 표시하지 않는다. 신청 시각이나 가짜 접수 ID도 만들지 않는다. 현재 범위는 안내까지이며 완료 화면을 새로 추가하지 않았다.

세 후속 단계의 개인정보 전문 복귀 위치를 공유 provider에 기록한다. 작성 초안의 원래 경로와 복귀 위치를 분리한 기존 구조를 확장해 현재 단계·작성값·걱정 선택·동의가 유지된다. URL·브라우저 저장소에 신청 정보를 기록하지 않는다.

## 구조·에셋·차이

route는 개발 제한·metadata·page composition만 담당한다. `pages-layer`가 호스트 shell과 widget을 조합한다. feature는 검증·개발 스냅샷·공유 상태를, widget은 사용자 흐름과 표시를 담당한다. 결과·소개서의 정적 레이아웃은 Server Component이고 금액과 버튼 등 상호작용은 Client 슬롯으로 전달한다.

기존 입력 화면의 4단계 진행 표시를 공통 feature UI로 분리해 결과·걱정·소개서 화면에도 재사용한다. 현재 단계는 색상과 `aria-current="step"`으로 표시한다.

기존 `host/room-income.png`와 `guest/budget-character.png`를 Figma의 동일 에셋으로 재사용했다. 새 다운로드·의존성 설치·테스트 프레임워크 추가는 없다. PC는 원본의 연 수익 강조와 결과 카드, 소개서 500/56/564 배치를 따른다. 모바일은 확정 기획대로 월 수익 → 연 수익 → 참고 조건 → 다음 행동 순서와 1열 걱정·소개서 배치를 사용한다.

개발 상태 안내, 고정 계약 예시 조건·규칙 버전, 실제 작성 조건의 확인 영역이 시안에 추가됐다. 원본의 실제 지역 평균가처럼 오인할 수 있는 문구는 사용하지 않았다. 선택 동의의 개발 설명 때문에 원본보다 세로 길이가 길다.

## 남은 단계와 정리

- 네 신청의 실제 저장 성공에 맞춘 결과·접수 완료 화면과 호스트 소개서 신청 완료 연결.
- 승인된 필수·선택 동의 전문/version 확인과 신한 BFF·세션·멱등 전송 계층 연결.
- 실제 계산 응답·걱정 저장·소개서 신청·직후 내역 조회, 저장 실패·같은 요청 키 재시도·세션 만료 검증.
- 미확정 걱정 건너뛰기·미동의·저장 실패 후 진행 동작은 확정 내용을 확인한 뒤 적용.
- 실제 모바일 기기·Safari·신한 앱 웹뷰 검증.

조사와 검증 요점은 이 보고서로 정리한다. 검증용 브라우저와 이번에 시작한 개발 서버를 종료하고 기존 개발 도구·의존성·캐시는 보존했다. 시작 시 개발 드라이브 여유 공간은 약 27GiB로 정리가 필요하지 않았다. 기존 미추적 기획·UTM 문서는 보존하고 커밋에서 제외한다. 서버·DB·관리자 코드 변경과 운영 배포는 수행하지 않았다.

후반 검증에서 8GB PC의 메모리 여유가 약 0.4~0.7GB로 줄어 개발 컴파일·검사가 지연됐다. 다음 단계에서는 브라우저 검증과 TypeScript/ESLint를 겹치지 않고 실행하며, 사용이 끝난 이번 작업의 브라우저·서버 프로세스만 종료한다. 의존성이나 공용 캐시 삭제로 처리하지 않는다.
