# 프런트 작업 목록 — 매물 등록·입주자 메인

2026-10-01. 아래는 작업 계획이며 코드 구현 완료 목록이 아니다.

## 기존 API 활용 구현 진행

- 메인의 Figma 시안 매물을 기존 GET /rooms 조회로 교체하고 실제 ID의 상세 링크 연결. 지역은 기존 region 문자열 부분 일치, 신규 영역은 createdAt 최신순으로 조회한다. 학교·역 검색 및 최초 게시일 정렬 구현을 의미하지 않는다.
- 상세 v2 DTO에 기존 areaRange·roomCapacity·거주원 소개·주의사항을 반영. 집 전체 면적 범위, 현재 거주 인원, 입주 가능 인원, 최소 거주 기간 표시 연결.
- 방 소개·현재 거주원 소개·생활 주의사항을 나누고 긴 설명 줄바꿈 유지.
- 등록 설명 안내·긴 placeholder 예시·2,000자 제한·카운터 추가. 예시 자동 저장 없음.
- 집주인 공개 상세 DTO에는 이름·가입일만 있어 자기소개 표시 연결은 서버 응답 보완 대기.
- 새 enum·0명 저장·소제목 저장·회원 동호수 비공개 서버 정책은 변경하지 않음.
- 지정 시험 매물: cf0b08c8-011e-4303-b1b8-57b0452c2c93. 실제 검증 결과는 별도 기록한다.
- 검증: TypeScript 검사 통과. 메인 페이지와 지역별/최신 매물 API HTTP 200, 브라우저에서 실제 매물명·상세 링크 확인. 개발 서버 컴파일 지연 및 브라우저 연결 시간 초과로 지정 매물 상세·로그인 회원 화면·이번 변경의 반응형 재검증은 미완료. 이전 시안 검증과 구분한다.
  연계: [백엔드 전달사항](listing-backend-handoff.md), [기준 기록](listing-data-decisions.md).

## API 회신 전 준비

- 등록·탐색 유형 레이블을 아파트/오피스텔/단독주택/쉐어하우스로 설계. 새 enum은 서버 지원 전 전송하지 않는다.
- 현재 거주 인원/입주 가능 인원을 별도 레이블로 표시. 거주 0명일 때 구성·성별 입력을 숨기고 해당 없음으로 전환. 서버의 null 규칙 확정 후 Zod·초기값·재개·autosave 연결.
- 집 전체 전용면적 범위 표기를 유지한다. 관리자 면적 보완 UI는 아직 만들지 않는다.
- 등록 설명에 안내와 긴 예시 추가. 안내: '학생들이 집과 생활환경을 이해할 수 있도록 방의 특징, 제공 시설, 주변 환경을 자세히 적어주세요.'
- 예시(설계안): '방에는 침대와 책상, 옷장이 준비되어 있고 창문으로 오전 햇빛이 들어옵니다. 주방과 세탁기는 정해진 생활 규칙에 따라 함께 사용할 수 있습니다. 집 주변에는 편의점과 마트가 있으며, 대중교통을 이용하기 편리합니다. 실제 제공하는 가구와 사용 가능한 공간, 함께 지켜야 할 규칙을 구체적으로 소개해주세요.'
- 예시는 도움말/placeholder로만 제공한다. 값으로 자동 저장하지 않으며 실제 매물에 없는 시설·거리·조건을 약속하는 문구로 사용하지 않는다. 긴 입력, 줄바꿈, 기존 2,000자 제한 표시를 고려한다.
- 관리자 소제목 입력·미입력·저장 중·오류·삭제 상태 UI 설계. API 연결 전 실제 저장 완료로 표시하지 않는다.

## API 확정 후 연결

- 주소 선택 결과에 시도·시군구·읍면동·코드 보존. 공급자 결과 Zod 검증 및 등록 DTO 변환.
- title은 서버 값을 사용: '노원구 공릉동의 아파트'. 각 카드에서 별도로 제목을 재생성하지 않음.
- draft 스키마·자동저장·재개, admin 소제목 mutation, 목록/상세 DTO·매퍼 연결.
- 거주 0명을 '정보 없음'으로 처리하지 않도록 null과 구분. 인원 구간 threeOrMore 유지.
- 상세 면적은 areaRange 레이블로 표시, 방 크기와 구분. 기존 자기소개 재사용.
- 일반 회원에게 층수만 표시하고 건물 동·호수는 표시하지 않음. 비회원 잠금 UI는 서버 preview 응답과 일치시키기.
- 관리자 주소 숨김 신규 UI 제외. 기존 API 삭제 작업 없음.
- 자유 검색·학교/역 연결은 추후 결정. 메인 검색창을 실제 검색 완료 기능으로 보고하지 않음.
- 실매물 카드는 실제 ID로 상세 연결. 메인과 탐색의 데이터 해석은 공유하고 디자인은 각 Figma 유지.

## dev 실매물 2~3개 검증

- 등록 → 관리자 검수·소제목 → 게시 → 메인·탐색 카드·상세 연결을 먼저 확인.
- 인원·유형·면적이 다른 매물과 긴 설명·여러 사진이 있는 매물 활용. 필요하면 동일 시험 매물 편집으로 추가 상태 확인.
- 주소·가격 누락 테스트는 이번 시나리오에서 제외. 입력 필수 정책은 유지.
- 방 등록 CTA 모드 변경·로그인 후 복귀 확인.
- ④ 카드·상세 데이터 일치 확인을 시험 등록에 포함한 뒤 ⑤ 검색·필터, ⑥ 지도, ⑦ 실데이터 디자인, ⑧ 전체 이관 순서로 진행.
- 상세 addressRegion 누락 오류 수정은 보류이며 정확 주소가 있는 실매물로 시험한다.
