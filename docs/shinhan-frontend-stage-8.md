## 구현과 경계

두 게스트 입력 화면의 연락처 단계에 **신청 후 화면 미리보기 (개발용)** 버튼을 추가했다. 조건·연락처·필수 동의가 유효할 때만 `/shinhan/dev/guest/followup`으로 이동한다. 기존 실제 접수 버튼은 계속 비활성이다. 연락처 입력 중 자정을 넘어 입주일이 과거가 되면 조건 단계로 돌아가 날짜를 다시 확인한다.

새 경로는 운영 모드에서 `notFound()`이며 예시 모델 생성도 development에서만 허용한다. 입력한 유형·조건·전화번호를 별도 스냅샷으로 복사한다. 실제 `applicationId`, 접수 시각, 전송 성공, 알림 상태는 만들지 않는다. 화면 상단에 미접수·미저장·미전송 상태를 명시한다. URL이나 브라우저 저장소에 신청 정보를 기록하지 않는다. 직접 진입하거나 새로고침해 스냅샷이 없으면 게스트 신청부터 시작하도록 안내한다.

걱정은 계약의 게스트 코드 6개를 사용한다. 여러 항목을 선택하고 개발 예시 동의를 체크해 선택별 가이드를 볼 수 있다. 계약대로 동의 후 빈 목록을 확인한 응답도 허용하며, 이를 아직 응답하지 않은 상태와 구분한다. 전체 확인 사항 보기는 가이드 표시 범위만 바꾼다. 기존 선택·동의·확인 응답을 바꾸거나 `SKIPPED`로 처리하지 않는다.

선택 동의의 승인된 전문은 아직 연결하지 않았다. 체크박스는 개발 예시임을 명시하며, 연결된 **기본 신청 개인정보 전문**은 걱정 항목의 선택 동의를 포함하지 않는다는 안내를 함께 제공한다. 새로운 법적 수집 목적·보유 기간·운영 동의 버전을 임의로 작성하지 않았다.

가이드의 **궁금한 점 전달하기**는 기획대로 입주 전 안내 화면으로 이동한다. 질문 입력이나 발송은 실행하지 않는다. 안내에서 내역으로 이동한 뒤 입력 조건과 확인한 걱정을 읽을 수 있다. 공간 사진은 원래 게스트 유형을 유지하는 조회 전용 화면이며 예산 경로의 **찾았어요**를 유지한다. 내역·사진에는 조건 편집이나 재접수 버튼이 없다. 함께 확인할 내용 다시 보기는 현재 가이드 범위를 유지한다.

개인정보 전문 복귀 위치와 초안의 원래 경로를 별도로 관리해 후속 단계에서도 유형·입력값·걱정 선택·동의·현재 단계가 보존된다. 기본 신청의 초안과 후속 화면의 조회용 스냅샷을 분리했다.

## 구조와 시안 차이

route는 개발 환경 제한·metadata·page composition만 담당한다. `pages-layer`가 shell, 후속 widget, 기존 공간 예시를 조합한다. feature는 입력 검증·예시 모델·공유 상태, widget은 흐름과 렌더링을 담당한다. Server Component로 가이드 본문·안내·캐릭터·브랜드를 구성해 Client 흐름에 슬롯으로 전달한다. 새로운 공통 UI나 테스트 프레임워크를 추가하지 않았다.

걱정·가이드는 PC 2열, 모바일 1열이다. 안내·내역은 PC 456/64/600 배치, 모바일은 소개 다음 카드 순서다. 기존 캐릭터·브랜드·공간 사진 3장을 재사용했다. 내역 카드에 개발 상태와 실제 입력한 조건을 추가했으며 개발용 동의 설명도 시안보다 길다. 접수 완료를 표시하는 대신 실제 저장 전임을 표시한다.
