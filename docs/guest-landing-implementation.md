## 구현을 위해 정한 값과 동작

- 모바일 시안이 별도로 지정되지 않아 390px/320px의 단일 열과 매물 2열, 중간 너비 3열을 적용했다.
- 전체 페이지는 서버 컴포넌트이며 검색, 카드 선택, FAQ, 등록 모드 전환, 요청 폼만 클라이언트로 분리했다.
- 공통 `SiteLayout`, 헤더, 푸터, `BtnCta`, `TextField`, `useAccountMode`를 재사용했다.
- 노원구 이외 지역은 시안 데이터가 없어 준비 안내를 표시한다. 해당 지역에 노원구 사진을 복제하지 않는다.
- 카드 hover/focus/press/선택에 Frame 269 색상을 적용했다. 실제 매물 상세로 이동하지 않는 시안용 선택 동작이다.
- 검색은 기존 `/rooms?q=...` URL로 이동한다. 기존 매물 조회 API에서 keyword 필터를 전송하지 않는 한계는 별도 후속 작업이다.
- 방 등록은 집주인 모드를 저장한 후 `/listing/new`로 이동한다. 로그인·등록 권한 검사는 기존 흐름을 유지한다.
- S2 API 미구현 안내·지역별 빈 상태 문구는 구현용 안내이며 Figma에서 가져온 문구가 아니다.
- 공통 헤더·푸터는 실제 제품 정보를 유지하여 Figma 자리표시자와 다르다.

## 남은 작업

1. **S2 저장·관리자 연결**: [API 제안](guest-region-request-api.md)의 인증·연락 수단·동의·중복 처리 정책 확정 후 백엔드 구현, 프론트 mutation 및 관리자 조회 연결.
2. **실매물 연결**: 실제 ID·지역·사진·노출 순서·신규 기준 확정. 시안 배열을 조회 API로 바꾸고 상세 페이지 연결, loading/error/empty 상태 추가.
3. **검색 계약**: 현재 `domains/room/api/room.api.ts`는 keyword와 지역 필터를 서버에 전달하지 않는다. 검색 파라미터와 정규화 정책을 백엔드와 합의해야 한다.
4. **등록 여정**: 로그인된 게스트 계정의 등록 권한, 비로그인 사용자 로그인 후 원래 등록 URL 복귀까지 실제 계정으로 통합 검증 필요.
5. **운영 콘텐츠**: 지역별 실제 매물, 익명 후기의 게시 승인, 최소 계약기간·24시간 문의 등 서비스 문구의 운영 일치 여부 확인.
6. **반응형 디자인 승인**: 모바일 배치·카드 열 수·가로 스크롤 카테고리는 구현 가정이므로 최종 모바일 시안과 대조 필요.
7. **공통 레이아웃**: Figma의 헤더 및 푸터와 기존 공통 구현 차이는 이 작업 범위에서 변경하지 않았다.

## 검증 기록

- TypeScript `tsc --noEmit`, 변경 파일 ESLint, `git diff --check` 통과.
- 1920px 데스크톱에서 원본 프레임과 구조·타이포그래피·에셋을 비교했고, 일러스트 export 여백으로 본문을 가리던 문제를 수정했다.
- 390px 모바일 화면의 히어로·FAQ 펼침 상태를 확인했고, 320px·390px에서 가로 넘침이 없었다. 최종 브라우저 오류 목록은 비어 있었다.
- 매물 카드 선택, 요청 폼의 빈 입력 오류와 유효 입력 시 API 미연결 안내, FAQ 답변 전환을 브라우저에서 확인했다.
- `/faq/guest` 직접 접근 시 원문 22문항 렌더링을 확인했다. 메인 링크의 클릭 직후 브라우저 도구가 타임아웃되어 링크 전환 자체의 최종 재검증은 남아 있다.
- 로그인 계정의 권한 변경·등록 완료, 검색 결과의 실제 필터링, 서버 저장·관리자 반영은 검증하지 않았다.
- 공통 헤더·푸터, 모바일 추정 배치, 원본에서 넘치는 콘텐츠를 수용하는 일부 섹션 높이는 원본과 차이가 있다. 픽셀 단위 완전 일치를 의미하지 않는다.
- 로컬 Turbopack은 상위 폴더의 잠금 파일 및 감시 경로 문제로 실패하여 `next dev --webpack`으로 검증했다. 프로덕션 빌드는 실행하지 않았다.
