## 아직 연결하지 않은 동작

- 본문의 방 등록·예상 월세 버튼은 원문을 유지한 비활성 버튼과 준비 중 안내다. 하위 신청 URL은 임의로 확정하지 않는다.
- 개인정보 전문은 이전 단계와 같이 미연결 상태다. 동의·저장·접수 완료를 흉내 내지 않는다.
- 고정 ‘예상 월세 진단’은 사용자 답변에 따라 처음부터 표시한다. 모바일은 하단의 작은 CTA 한 개로 바꾸고 본문 동일 진단 버튼이 보일 때 숨긴다. 이번 단계에서는 계산 입력 없이 준비 중인 진입 버튼만 표시한다.
- 본문 1200px과 오른쪽 패널의 겹침을 줄이기 위해 1848px 이상에서 오른쪽 300px 패널, 그 미만에서 작은 하단 바로 전환한다. 따라서 검증한 PC 1440px에서도 하단 바가 표시된다. 하단에 104px + 안전 영역 여백을 확보했다.
- 시안의 운영 숫자·후기는 디자인에 제시된 정적 콘텐츠이며 이번 단계에서 최신 운영 데이터로 검증한 값이 아니다.
- 원본 FAQ의 ‘집주인가/집주인와’ 조사 오타와 입주 후 관리 설명에 반복된 학생 확인 문구는 원문 보존 요구에 따라 유지했다. 문구 교정은 별도 확정이 필요하다.

모바일 검증 중 MBC·지역 활동 사진의 384px WebP 응답이 개발 서버에서 지연됐다. 원본과 PC 크기 응답은 정상이었으며, 이번 작업에서 실행한 개발 서버만 재시작한 뒤 모바일 응답과 브라우저 로딩을 재확인했다. 의존성·캐시를 삭제하거나 이미지 최적화를 우회하지 않았다.

증거 이미지는 작업 시각화 폴더의 `shinhan-host-desktop.jpg`, `shinhan-host-desktop-full.jpg`, `shinhan-host-mobile.jpg`, `shinhan-host-mobile-full.jpg`에 저장했다. 실제 휴대폰·Safari·신한 앱 내 웹뷰와 운영 환경 검증은 수행하지 않았다. 신청 저장·실패·재시도 검증은 해당 기능 및 실제 API 연결 단계에서 수행한다.

## 단계 전환과 작업 정리

- 이전 정적 검사 세션의 정상 종료를 확인했다. 불필요한 이전 Figma 응답 캐시를 해제하고 이 문서에 필요한 근거만 남긴다.
- 이전 실패한 브라우저 탭은 내부 오류 페이지의 보안 정책으로 접근이 거부되어 자동 정리하지 않았다. 정상 검증은 별도 localhost 탭에서 진행한다.
- 개발 환경·의존성·빌드 캐시는 유지했다. 이번 시작 시 C 드라이브 여유 공간은 약 13.2GiB로 정리 기준 5GB 이상이다.
- 앞으로도 각 단계 결과와 남은 일을 문서로 인계하고, 사용자 요청에 따라 단계별 커밋을 생성한 뒤 메시지·해시를 보고한다.
- 다음 단계는 `/shinhan/guest` 소개 화면 한 개다. 신청 기반·네 신청 흐름·후속 화면·실제 API 통합 검증은 그 뒤에 나누어 진행한다.
