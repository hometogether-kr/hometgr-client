# 8단계 통합 검증

2026-10-16 · `feat/listing-exploration-release`

## 판정

프론트에서 확인 가능한 공개 API·코드·모의 등록 검증을 진행하다가 **사용자 요청으로 전체 QA를 중단했습니다.** 추가 브라우저 QA·전체 린트 재시도·빌드는 진행하지 않습니다. 실등록 → 관리자 게시 → 수정·비공개 전환의 종단 검증은 수행하지 않았습니다. 실계정 인증도 앞서 합의한 대로 보류했습니다.

## 이번 수정

- 홈의 지역별·신규 매물 목록도 재진입 때 최신 데이터를 조회합니다. 기존 목록 API를 그대로 사용하며 상세 링크의 사전 조회를 끕니다.
- 사진을 10장씩 나누어 올리다가 뒤 묶음이 실패하거나 응답이 유실되면, 초안 상세와 목록을 무효화하고 활성 조회를 다시 받습니다. 이미 저장된 사진과 최신 version을 복원한 후 남은 사진을 올릴 수 있습니다. 실패한 업로드를 자동 재전송하지 않습니다.

앱 내 브라우저 연결 오류로 설치된 Edge의 격리된 headless 브라우저를 사용했습니다. 사진 검증에서는 로컬 전용 가짜 세션과 모의 API만 사용했고, 원격 등록·업로드·수정 요청은 보내지 않았습니다.

기존 지역 선택 일치·누적 목록·스크롤 복원·회원 지도 예시 검증은 [6단계](listing-stage-6-verification.md), [7단계](listing-stage-7-verification.md)에 구분해 기록돼 있습니다. 이번 실제 공개 매물 1개로 다중 페이지를 검증했다고 주장하지 않습니다.

## 효재님 확인 필요 — 월세 단위

공개 화면의 확정 정책은 **응답 30 = 30만원**이며 유지했습니다. 반면 배포 명세의 `Step8PricingDto.monthlyRentKrw`, `DraftPricingDataResponse`, `AdminRoomUpdateRequestDto`는 여전히 원 단위·예제 500000입니다. 현재 호스트 등록 화면은 “30만원”을 `300000`으로 보내고, 저장값도 숫자 그대로 복원합니다. 로컬 백엔드의 제출·공개 serializer는 단위 변환 없이 값을 전달하지만, 이를 최신 배포 동작의 증거로 간주하지 않습니다.

따라서 신규 등록부터 공개 조회까지 값이 같은 의미인지 확인해야 합니다. 금액 크기에 따라 단위를 추측하는 보정이나, 확인 없는 쓰기 단위 변경은 넣지 않았습니다.

> 공개 API의 월세 30은 30만원 기준으로 프론트에 반영했습니다. 신규 등록 `Step8PricingDto.monthlyRentKrw`도 30만원을 `30`으로 보내는 계약인지, `300000`원으로 보내면 공개 조회에서 변환하는지 확인 부탁드립니다. 초안 저장·재조회, 제출, 관리자 수정, 공개 조회 각각의 입력·응답 예시를 같은 매물 기준으로 알려주세요. 현재 배포 명세는 원 단위이고 호스트 등록은 그 기준으로 전송하고 있습니다.

## 참고용 미검증 항목 — 사용자 요청으로 QA 생략

1. 로그인 가능한 개발 환경에서 전용 검증 매물 등록 → 사진 업로드·자동저장·이어쓰기 → 제출.
2. 관리자에서 상세 설명·선택 부제목·가격 저장 → 주소 확인 → 게시 → 홈·구 목록·검색·상세 확인.
3. 관리자 수정·비공개 → 목록 복귀 재조회·상세 안내, 주소 변경 → 공개 중단 → 재확인·재게시, 필요 시 검증 매물 삭제.
4. 사용자 요청으로 보류한 실제 OAuth 완료·유효 토큰 갱신·회원 buildingAddress와 지도·회원→비회원 전환.
5. 운영 도메인의 카카오맵 허용 설정과 지도, 카카오 채널 연결.

관리자 로컬 코드에는 설명 수정과 선택 부제목 저장이 있습니다. 월세 라벨은 아직 `월세(원)`이므로 기존 만원 표시 수정 요청의 배포 반영 여부를 확인해야 합니다. 관리자 저장소는 수정하지 않았습니다.

희망 지역 요청·개인 알림 정책은 기존 미확정 항목으로 남깁니다. 이번 작업은 해당 계약을 확정하거나 실제 문의·알림을 전송하지 않았습니다.
