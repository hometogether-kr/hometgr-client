# 한 달 월세 지원 이벤트 기획안

전단지 QR로 유입된 학생의 신청 정보를 수집한다. 여러 학교에서 같은 양식을 사용한다. [Slack 요청](https://hometohq.slack.com/archives/C0BT7FJ36F9/p1794807866106499)

## 학생 신청

- 전단지 QR과 신청 주소는 `https://hometogether.kr/event_1`이다. 학생은 로그인 없이 희망 대학·캠퍼스와 희망 입주 시점(연도·월·초/중순/말)을 필수로 입력하고, 휴대전화·이메일과 개인정보 수집·이용 동의를 제출한다. [입주 시점 추가 작업](move-in-timing.md)
- 휴대전화는 입력할 때 `010-0000-0000` 형식으로 표시한다. DB 저장 성공 후 연락처를 일부 가린 완료 화면과 **처음으로** 버튼을 표시한다.
- 신청과 알림톡 발송 작업을 함께 저장한다. 알림톡 템플릿 승인을 반영해 2026-11-22 발송을 활성화했다. 저장 직후 접수 완료와 대기 안내를 요청하며 매물 링크는 제외한다. [알림톡 연결과 활성화](alimtalk.md)

## 운영 화면

- 이벤트 앱의 `/event_1/ops`에서 행사 전용 비밀번호를 입력한 운영자가 **학교·희망 입주 시점·전화번호·이메일**을 조회한다. 비밀번호는 4~128자로 설정하며, 쿠키 서명 키는 별도의 긴 값으로 관리한다. 연락처는 가리지 않으며 검색·상세 화면·알림톡 상태 표시는 두지 않는다.
- 행사 종료 시 새 신청을 닫고 같은 주소에서 종료를 안내한다.

## 개발과 배포

- `hometgr-client`의 `event_1` 워크트리와 `feat/event_1` 브랜치에서 신청 화면, 운영 화면, Next.js Route Handler, 알림톡 워커 코드를 관리한다. 워커는 웹 요청과 별도로 실행한다.
- 이벤트 앱은 본 사이트와 별도로 배포하고 행사 전용 환경 변수를 사용한다. **Supabase의 `hometogether-dongduk-landing` 프로젝트에 행사 전용 `event_1` 스키마**를 두고, 행사 테이블에 권한을 가진 서버 계정으로 연결한다.
- 공용 도메인에서는 `/event_1`과 하위 경로만 이벤트 앱으로 연결한다. Cloudflare 라우터 설치 후 행사 앱의 배포 주소를 지정한다. [도메인 설정](domain.md)
- Figma의 대학 입력·연락처 입력·신청 완료 화면을 독립 앱에 구현했다. 데스크톱 1440px과 모바일 390px에서 비교하고, 완료 버튼은 요청대로 `처음으로` 하나만 둔다. [Figma 원본](https://www.figma.com/design/bDb6mnswp2gh0cmHKi13uU?node-id=820-1605) · [완료 버튼](https://www.figma.com/design/bDb6mnswp2gh0cmHKi13uU?node-id=832-664)

## 개발 순서

1. **착수 준비** — `hometgr-client`에 `event_1` 워크트리를 만들고 기획서를 옮긴다. 도메인 경로 연결과 DB 생성 권한을 확인하고, 알림톡 템플릿 승인과 행사 종료일·개인정보 동의 문구·보관 기간 확정을 병행한다.
2. **DB와 접수** — Supabase에 행사 스키마와 접속 계정을 준비한다. Next.js 접수 API와 `/event_1` 폼을 연결해 저장 성공·실패와 중복 제출을 확인한다.
3. **운영 조회** — `/event_1/ops`와 조회 API를 연결한다. 운영자 비밀번호로 인증한 뒤 학교·전화번호·이메일을 조회하고, 인증 전 API 호출은 차단한다.
4. **알림톡** — 저장된 발송 작업을 워커에 연결한다. 테스트 번호로 접수 직후 수신과 실패 재시도를 확인한다.
5. **공개** — Figma 기준 화면과 Supabase 연결을 확인하고 이벤트 앱을 별도 배포한다. 전단지 QR부터 접수·알림톡까지 검증하고, 기존 사이트의 로그인과 주요 페이지가 정상 동작하는지 확인한다.
