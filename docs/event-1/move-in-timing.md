# 희망 입주 시점 추가

작업 브랜치: `feat/event-1-move-in-date` (`feat/event_1`의 `88f1a80`에서 분기).

- 대학 입력 단계에서 연도 4자리, 월(1~12월), 시기(초·중순·말)를 **필수**로 받는다. 예: `2027년 3월 중순`.
- 다음 단계에서 선택 내용을 확인하고 변경할 수 있다. 제출 오류나 이전 단계 이동 시 값을 유지하며, 신청 완료 화면에서도 표시한다. `처음으로`는 세 필드를 모두 비운다.
- 운영자 목록과 모바일 카드에 희망 입주 시점을 추가한다. 기존 신청의 누락 값은 `미입력`으로 표시한다.
- API의 `moveInTiming`을 서버에서도 검사한다. 새 신청에서 값이 누락되거나 일부만 있으면 400이며, 같은 제출 키로 입주 시점을 변경하면 409다.

```json
{
  "moveInTiming": { "year": 2027, "month": 3, "period": "mid" }
}
```

`period`는 `early`(초), `mid`(중순), `late`(말)이다. 연도 범위는 2000~~2100, 월은 1~~12다. 특정 일자를 추정해서 저장하지 않는다.

DB 마이그레이션은 `apps/event-1/supabase/migrations/20261122063804_event_move_in_timing.sql`이다. `event_1.event_applications`에 `move_in_year`, `move_in_month`, `move_in_period`를 추가한다. 기존 기록 보존을 위해 세 값이 모두 NULL인 경우를 허용하며 일부 값만 있는 상태는 DB 제약으로 막는다. 기존 DB 권한이나 다른 스키마는 변경하지 않는다.

현재 마이그레이션과 기능은 **로컬에서만 검증했으며 공개 행사 앱에는 아직 배포하지 않았다.** 공개 시에는 이 마이그레이션을 먼저 적용하고 행사 앱을 배포한다. 알림톡 승인 반영은 기존 공개 버전으로 별도 재배포해 완료했다.

검증은 추가 기능에 한정했다. `npm run verify:move-in`으로 필수 입력·범위·세 시기 저장·동일 요청 재시도·날짜 변경 충돌·기존 NULL 표시·운영자 조회를 확인한다. 브라우저에서는 320px·390px·1440px에서 새 입력 필드, 필수 안내와 포커스, 단계 이동 시 보존, 완료 표시, 초기화를 확인했다. 기존 도구 연결이 응답하지 않아 설치된 Edge의 별도 headless 프로필을 사용했으며 추가 도구를 설치하지 않았다. 모든 자료는 합성 정보이며 실제 로컬 DB만 사용했다.
